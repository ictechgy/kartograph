# 변경 전 조사와 MCP 비교

첫 16회 비교에서는 MCP의 효용을 확인하지 못했다. 알려진 검토 기준 점수는
소스 조건 **27/34**, MCP 조건 **26/34**였고, MCP 조건의 시간·비용·표시된 도구 출력량도
증가했다. 실제 도구 연결을 AI 생산성 향상으로 해석하지 않는다.

[사전 프로토콜](PROTOCOL.md), [고정 표본](cohort.json), [독립 검토 기준](oracle.json),
[16회 전체 결과](results-v1.json)를 함께 제공한다. 이 결과는 과거 일반 코드 수정의
각 조건 6/12 통과·graph query 0회 결과와 다른 작업이다.

## 조건과 결과

주어진 production 변경을 적용하기 전에 조사할 **기존** 테스트·호출자·override·등록 지점을
최대 12개 찾게 했다. 두 조건 모두 같은 원본 소스 읽기·검색·목록 도구를 사용했다.
MCP 조건에만 실제 kartograph의 `query_symbol`, `impact`, `freshness`를 추가했으며
호출을 강제하지 않았다. Claude Code 2.1.270, `claude-opus-5[1m]`, effort low,
전체 도구 예산 12회·900초·최대 추정 비용 $3을 적용했다. 저장소별 각 조건을 두 번 실행했다.

각 칸은 **소스 / MCP**의 두 반복 평균이다. 기준은 완전한 동적 영향 정답이 아니라
모델 실행 전에 javap·원본 source·실제 기존 테스트 실행으로 고정한 검토 대상이다.
정확한 대상은 1, 파일·클래스 수준 확인은 0.5다.

| 공개 변경 | 기준 coverage | 모델 세션 시간(초) | CLI 비용 추정($) | 표시된 도구 내용(bytes) |
|---|---:|---:|---:|---:|
| Gson #1093 | 50.0% / 41.7% | 45.1 / 44.8 | 0.223 / 0.263 | 17,231 / 24,657 |
| Jackson Core #1172 | 100% / 100% | 44.9 / 48.5 | 0.221 / 0.274 | 16,487 / 25,516 |
| detekt #7715 | 87.5% / 87.5% | 25.8 / 27.5 | 0.118 / 0.117 | 8,605 / 7,303 |
| ktlint #2891 | 100% / 100% | 36.6 / 59.4 | 0.169 / 0.314 | 8,303 / 28,492 |

MCP 8회에서 실제 제품 도구 요청은 18회였다. 여기에는 신선도 검사와 실패한 질의도 포함하며,
그 수를 효용 점수로 쓰지 않는다. 16회 모두 유효한 최종 답변을 반환했고 연결·실행 오류는 없었다.
예산 이후 추가 요청은 거부했다. 전체 요청 수와 실제 처리 수를 결과 파일에 각각 기록한다.

## 확인한 실패 원인

Gson 두 반복은 `com.google.gson.stream.JsonWriter.value(double)`과 `JsonWriter.value`를
질의했다. 기존 exact-name/USR 문법에 맞지 않아 `notFound`가 되었고, 원래 overload의
호출자를 찾지 못했다. 임의로 overload를 선택해서 해결할 문제는 아니다.

Jackson 두 응답과 ktlint 한 응답은 서버의 1 MiB 전송 한도 안이었지만 Claude의 표시 한도를
넘었다. 클라이언트가 별도 파일 안내로 바꿨고, 격리된 실험에는 그 파일을 읽는 일반 도구가
없었다. 이 **3건의 표시 실패**는 프로토콜 성공과 구분한다. 전체 원시 응답을 보냈다고 해서
모델이 그 내용을 읽은 것으로 세지 않았다.

소스 읽기 50건과 검색 결과 437건을 원본 Git source와 대조했으며 모두 일치했다.
proxy가 전달한 제품 결과도 원본과 같았다. 이전 코드 수리 실험에서 발견했던 입력 정제 오류와
구분되는 이번 인터페이스 문제다. 모델에 정답 패치·새 회귀 테스트·평가 대상 목록을 주지 않았다.

## 설명과 채점 감사

조건명을 가린 답변을 먼저 읽었다. 답변 내용이 도구 사용을 밝히는 경우가 있어 완전한 맹검은
아니다. 이름을 댄 파일은 모두 원본에 존재했고 삭제·테스트 생략을 승인한 답변은 없었다.
추가 후보는 자동으로 오탐 처리하지 않았으며, 다음 설명 오류를 별도로 기록했다.

- 두 소스 조건의 ktlint 답변은 `!= FUNCTION_LITERAL`의 참·거짓을 반대로 설명했다.
  MCP 답변에도 서로 모순되는 설명이 일부 있었다.
- detekt의 일부 답변은 인자가 있어 보고되지 않는 외부 호출까지 inner/outer finding 순서가
  바뀐다고 설명했다. 실제 표본의 assertion은 개수만 확인한다.
- Gson의 일부 답변은 Number overload를 거치는 기능 테스트를 수정된 double overload의
  직접 검증으로 잘못 연결했다. 다른 답변은 이 경로를 미확인으로 명시했다.
- 한 MCP 답변은 새로 추가될 메서드를 기존 검토 대상으로 포함했다. 해당 항목에는 기존 대상
  점수를 주지 않았다.

채점기의 `Factory (registration site, line 18)` 같은 **클래스 뒤 설명** 처리가 원래 정한
0.5 부분 점수를 놓쳤다. 원래 결과 [26/34 · 25/34](results-v1-frozen-grader.json)를 보존하고,
실패/통과 회귀로 채점기를 수정한 뒤 같은 16개 답변을 모두 다시 계산했다. detekt 양쪽 조건에
같은 부분 점수가 추가됐고, 다른 대상·overload 규칙과 음성 결론은 바뀌지 않았다. 모델을
다시 실행하거나 정답 대상을 늘리지 않았다.

## 준비 비용과 한계

세션 시간은 모델 실행과 연결·snapshot 로딩을 포함한다. 다음 준비 비용은 별도이며, 전체 CI
시간으로 합성하지 않는다. 원래 소스의 focused 테스트와 필요한 compile을 실제 수행했다.

| 입력 | 빌드 도구가 기록한 원본 검증 시간 | snapshot capture 시간 |
|---|---|---:|
| Gson | compile 2.9초, focused test 2.0초 | 0.75초 |
| Jackson | release parent를 쓰는 대체 POM compile 3.5초, test 3.8초 | 1.01초 |
| detekt | focused test 211초, 나머지 testClasses 28초 | 4.17초 |
| ktlint | focused test 89초, 나머지 testClasses 13초 | 2.57초 |

위 숫자는 로컬 dependency cache를 사용하는 검증 명령의 시간이다. 초기 다운로드·환경 문제
조사·정답 작성 비용을 제품 속도로 섞지 않으며, 최초 clean CI 비용은 이 표로 알 수 없다.
Jackson의 미배포 `2.17.0-SNAPSHOT` parent 대신 별도 POM에서 정식 `2.17.0`을 사용했다.
원본 production/test source는 바꾸지 않았다. 네 수동 snapshot에는 compiler witness가 없어
제품 신선도는 모두 `unverified`였고, 이를 `matched`라고 바꾸지 않았다.

4개 공개 변경·한 모델·두 반복이므로 통계적 우위나 다른 코딩 에이전트 전체로 일반화할 수 없다.
공개 이슈의 모델 학습 이력도 알 수 없다. 원본 코드·대화·절대경로 binding은 로컬에 보관하고
공개 파일에는 측정 요약·근거 식별자·해시를 남긴다.

## 실행 도구

`run.py`는 native Claude CLI와 `session_mcp.py`를 사용하며, 먼저 `--prepare-only`로 입력·
도구·바이너리·oracle 해시를 고정한 뒤 `--execute-prepared`로 한 번 실행한다. 시작한 디렉터리를
덮어쓰거나 선택적으로 재시도하지 않는다. `grade.py`는 저장된 답변과 고정 oracle을 채점한다.
`collect_direct_oracle.py`는 javap의 직접 참조를 수집하며 제품 graph를 정답으로 사용하지 않는다.
새 표본에는 `--inputs <native-inputs.json> --targets <targets.json> --javap <JDK/bin/javap>`을
명시한다. 입력의 `classRoots`는 고정 checkout 안의 실제 디렉터리여야 하고, `targets`는
JVM owner에서 `method:descriptor` 목록으로의 매핑이다(`null`은 해당 owner의 직접 참조 전체).
실제 javac 표본에서 정확한 overload만 수집하고 checkout 밖 root를 거부하는 검증을 유지한다.

실험용 source 도구는 추적된 Java/Kotlin/build 파일만 열며 12회 공통 예산과 파일/출력 상한을
적용한다. `O_NOFOLLOW`와 directory FD, Unix select를 쓰므로 현재 실행기는 macOS/Linux용이다.
현재 native 실행의 JDK 설정은 macOS JDK 21 경로이며, 다른 환경에서는 실행 전에 자신의 JDK로
설정하고 새 manifest를 고정해야 한다. 실행한 파일 해시와 원본 v1 바이너리는 로컬에 보존했다.

확인된 심볼 복구·표시 한도를 보완한 다음 비교는 이번 네 변경을 개발 자료로 분리하고,
새 변경과 정답을 결과 관찰 전에 다시 고정해 수행한다. 아직 후속 효용 결과를 주장하지 않는다.

## 후속 v2 결과

요약 한도를 보완하기 전 두 번째 16회도 음성이었다. [새 표본](cohort-v2.json)과
[14개 독립 기준](oracle-v2.json), [전체 결과](results-v2.json)를 보존한다.
소스 조건은 **16/28**, MCP 조건은 **10.5/28**이었다. 같은 가중치의 두 반복 평균은 다음과 같다.

| 공개 변경 | 기준 coverage(소스 / MCP) | 세션 시간(초, 소스 / MCP) |
|---|---:|---:|
| fastjson2 #2559 | 33.3% / 0% | 50.7 / 54.5 |
| Jackson Core #1142 | 100% / 100% | 44.4 / 49.8 |
| detekt #7667 | 100% / 100% | 52.7 / 56.6 |
| ktlint #2873 | 50% / 31.3% | 62.9 / 60.2 |

전체 평균 시간은 52.68 / 55.27초, CLI 추정 비용은 $0.278 / $0.286이었다.
연결·실행 오류는 없었지만 MCP 답변 하나가 요구한 JSON으로 파싱되지 않아 0점으로 포함했다.
빈 응답은 아니며, 저장된 원문 6,149자는 로컬에 유지했다. 나머지 15개 답변의 대상 파일은 모두 존재했다.
독립 검토자는 조건명·점수·oracle을 읽기 전에 원본 source와 답변을 대조했다. 설명이 도구 사용을
드러내는 경우가 있어 완전한 맹검은 아니다. 삭제·테스트 생략 승인 주장은 관찰하지 않았다.

소스 읽기 73건·검색 결과 579건은 원본과 일치했고 제품 결과도 proxy에서 변형되지 않았다.
클라이언트 출력 파일 대체는 **0건**으로 줄었다. 심볼 후보 안내도 실제 정확한 USR 재질의로
이어졌으나, fastjson2의 가장 작은 정확한 메서드 영향 보고서가 47,864 bytes였고 그중
43,109 bytes가 전역 summary였다. 후보 한 개·경로 한 개로 줄여도 16 KiB 안에 들어가지 않아
3회가 명시적인 크기 오류로 끝났다. 영향 후보를 없애거나 표본을 제외할 문제가 아니라,
전역 요약 항목의 출력 한도를 따로 제공해야 하는 제품 결함이다.

fastjson2 답변 일부는 등록된 converter의 입력 의미를 잘못 설명했다. 원본 `ToDouble.apply`는
Number를 받으며, 실제 의존성의 javap 결과도 `Decimal128 extends Number`다. 이 타입이 Number가
아니라서 반드시 실패한다는 주장은 맞지 않는다. `getTypeConvert`도 정확한 타입 키를 조회하며
상위 Number 타입으로 자동 탐색하지 않는다. 이런 설명 오류를 단순 대상 coverage와 분리했다.

큰 입력의 첫 capture는 기본 64 MiB 한도를 넘어 실패했다. 원본 core와 전체 test 출력 범위를
유지한 채 `--snapshot-max-mib 128`을 구현해 88,695,953-byte snapshot을 캡처했다.
로컬 JDK 21의 capture 7.60초·최대 RSS 2.57 GB, 기본 heap의 saved query 2.24초·1.86 GB,
`-Xmx1g` query 1.93초·1.28 GB를 기록했다. 두 query 결과는 바이트가 같았다. 다른 세 snapshot
capture는 Jackson 1.11초, detekt 4.41초, ktlint 2.61초였다. 준비 비용과 JVM heap 밖 메모리까지
포함한 RSS를 AI 세션 성능·정확도 개선으로 해석하지 않는다.

원본 빌드·focused 테스트는 fastjson2 34, Jackson 17, detekt 2, ktlint 86개가 모두 통과했고
새 PR 테스트를 주입하지 않았다. kotlin parameterized 테스트의 중복 표시 이름은 메서드 식별자로
사용하지 않고 원본 선언·javap descriptor로 확인했다. 새 비교에서도 compiler witness는 없어
신선도 `unverified`를 유지했다. 두 음성 결과의 표본은 이후 개발·회귀 자료로만 사용한다.

## 후속 v3 결과와 판단

전역 요약을 별도로 제한한 후 [다음 표본](cohort-v3.json)과 [20개 검토 기준](oracle-v3.json)을
고정해 16회를 더 실행했다. [전체 결과](results-v3.json)의 점수는 소스 **16.5/40**, MCP **24.5/40**다.
평균 세션 시간은 51.68 / 55.75초, CLI 추정 비용은 $0.263 / $0.269였다.

| 공개 변경 | 기준 coverage(소스 / MCP) | 유효 JSON 답변(소스 / MCP) |
|---|---:|---:|
| fastjson2 #2285 | 40% / 50% | 2/2 / 2/2 |
| Jackson Core #1053 | 33.3% / 66.7% | 1/2 / 2/2 |
| detekt #7635 | 43.8% / 81.3% | 1/2 / 2/2 |
| ktlint #2823 | 50% / 50% | 2/2 / 2/2 |

이 점수 차이를 그래프 분석의 AI 효용으로 주장하지 않는다. MCP 조건의 실제 제품 호출 9회 중
8회는 신선도 검사였고, 분석 질의는 `query_symbol` **1회**, `impact` **0회**였다. 소스 조건의
형식 실패 2건도 0점으로 포함됐다. 작은 공개 표본의 응답 형식·탐색 선택 차이를 제거한 효과가
아니며, 여러 사례에서 반복된 그래프 기반 개선은 확인하지 못했다.

16회 모두 provider 실행은 끝났으며 연결·실행 오류는 없었다. 소스 읽기 83건과 검색 결과
527건은 원본과 일치했고, proxy 결과 변형·클라이언트 출력 파일 대체는 없었다. 14개 파싱 가능한
답변의 대상 파일은 모두 존재했다. 나머지 두 건은 각각 8,343자·5,741자의 응답을 반환했지만
엄격한 JSON 파싱에 실패했다. 빈 응답으로 바꾸어 설명하거나 같은 모델 실행을 재시도하지 않았다.

독립 검토는 조건명과 점수·oracle을 보지 않은 상태에서 원본 source를 대조했다. 여러 답변에
Jackson의 singleton identity·비교 순서, fastjson2의 메서드 소유자·기존 호환 annotation 처리,
ktlint의 이미 명시된 기본 설정, detekt의 설정 생성 테스트 범위에 대한 오해가 있었다.
이 근거는 결과 파일에 대상 발견 점수와 별도로 보관했다. 도구 사용을 드러내는 본문 때문에
완전한 맹검은 아니며, 삭제·테스트 생략을 승인한 주장은 관찰하지 않았다.

원본 focused 테스트는 fastjson2 4, Jackson 12, detekt 27개가 통과했다. Ktlint는 보고된
252건 중 248건을 실행했고 기존 건너뜀 4건을 유지했다. 새 테스트를 주입하거나 건너뜀을 통과로
세지 않았다. 여러 commit으로 구성된 Kotlin PR은 모델·oracle 노출 전에 최종 production diff로
정규화하고 고정 base에 적용 가능한지 확인했다. 원본 mail series도 남겼다. Jackson의 기존
`2.16.0-SNAPSHOT` parent는 실제 해석에 실패했으므로 별도 POM의 정식 `2.16.0`으로 빌드했으며,
원본 POM/source는 보존하고 대체 POM을 snapshot build 입력에 명시했다.

세 차례 **48회 전체 결과**는 제한된 인터페이스 결함을 찾고 고치는 근거다. 심볼 재탐색,
출력 한도, 큰 snapshot, 전역 요약의 실제 실패는 회귀 검증으로 개선했다. 일반적인 AI 생산성은
미입증으로 남긴다. 검증된 캐시·정적 분석·MCP·CI 기능의 배포와 추가 AI 효용 연구를 구분하며,
원하는 점수가 나올 때까지 같은 사례를 반복하거나 유리한 결과만 공개하지 않는다.

## 최종 채점·입력 감사

외부 리뷰에서 긴 Kotlin 테스트 이름의 접두어를 다른 메서드로 인정하는 채점 결함을 찾았다.
정확한 메서드 목록·호출 지점 설명은 인정하면서 이름 전체를 구분하는 회귀 검증을 추가하고,
고정 oracle과 원본 48개 답변을 모두 다시 채점했다. v2의 소스 조건 두 답변에서 각각 1점이
제거됐다. v1의 27/34 · 26/34와 v3의 16.5/40 · 24.5/40은 그대로다. 모델 재실행이나 oracle
변경은 없었다. 직전 [v1](results-v1-before-final-review.json),
[v2](results-v2-before-final-review.json), [v3](results-v3-before-final-review.json) 결과를 보존하며,
현재 결과에는 채점기 해시와 JSON 문법·형태·대상 수 초과의 구분을 기록한다.

실행기도 준비·재개 시 고정 HEAD와 추적 파일 상태를 함께 검사하고, 소스 도구가 읽을 수 없는
1 MiB 초과 입력은 준비 단계에서 거부하도록 보완했다. 완료된 12개 checkout의 13,911개 소스를
다시 대조해 HEAD와 manifest 해시가 일치하고 모두 크기 한도 안임을 확인했다. 이 추가 검사를
과거 실행 시 이미 시행한 것으로 표현하지 않는다. 별도의 대체 빌드 POM과 원본 소스는 구분한다.
