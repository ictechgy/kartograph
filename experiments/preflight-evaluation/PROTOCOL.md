# 변경 전 영향 점검 비교

이 실험은 주어진 production 변경을 적용하기 전에 조사할 기존 호출자·테스트·계약을
찾는 작업이다. 과거 일반 코드 수리의 source 6/12·impact 6/12 및 실제 graph query
0회 결과는 별도 결과로 유지한다.

4개 공개 저장소의 새 변경을 고정하고 각 조건을 두 번 실행한다. 동일한
`claude-opus-5[1m]`, effort low, 공통 source 도구, 총 도구 호출 12회, 벽시계 900초,
최대 비용 3 USD를 사용한다. source 조건에는 list/read/literal-search만 제공한다.
MCP 조건에는 같은 source 표면에 실제 제품의 query_symbol/impact/freshness를 추가한다.
제품 도구 호출을 강제하거나 호출 횟수를 효용 점수로 환산하지 않는다.

실행 디렉터리는 저장소 밖의 빈 임시 디렉터리다. 개인·프로젝트 설정, CLAUDE.md,
auto-memory, skills, 일반 파일·실행 도구를 끄고 명시한 MCP만 제공한다. 인증은 기존
Claude CLI가 처리하며 키·인증파일을 읽거나 복사하지 않는다. safe mode는 명시한
MCP도 비활성화하므로 사용하지 않는다. 실행 flag와 실제 발견된 도구 목록을 기록한다.

모델에는 동일한 원본 source 접근과 production 변경만 제공한다. 숨긴 테스트 변경,
Gold 결과, 평가 대상 목록, 이전 모델 결과는 제공하지 않는다. 새로운 테스트는 원래
그래프와 정답에 넣지 않는다. 원본 source·artifact·도구·prompt·oracle 해시를 실행 전
고정하고 모든 tool input/output 및 최종 응답을 남긴다. source/graph 호출은 동일한
예산을 공유한다. proxy는 실제 제품 MCP의 스키마·결과를 그대로 전달한다.

답변은 최대 12개 기존 조사 대상에 대해 파일, 가능한 정확한 메서드/호출 지점,
분류(test/caller/override/registration), 이유와 근거를 포함한다. 파일 수준만 확인했으면
그 사실을 밝힌다. 수정·삭제·테스트 생략이나 런타임 영향의 완전한 증명을 요청하지 않는다.

평가는 모델 실행 전에 독립적으로 고정한 알려진 조사 기준을 사용한다. 직접 호출은
javap의 method reference로, 테스트는 원본에서 실제 실행한 기존 테스트로 확인한다.
Gson의 기존 override 하나는 원본 선언으로 확인한다. 이것은 완전한 동적 영향 정답이 아니다.
정확한 대상 일치는 1, 테스트 파일/클래스만 지목한 경우에는 해당 기준당 0.5를 기록한다.
추가 대상은 자동으로 오탐이라고 단정하지 않고 별도로 근거를 검토한다.

기준별 coverage, 설명의 근거 일치, 근거 없는 안전/완전성 주장, 추가 조사 대상 수,
읽은 파일·줄·바이트, 실제 도구 사용, 시간·비용을 함께 보고한다. 가능한 경우 조건명을
가린 응답으로 설명을 평가한다. 제품 준비 비용은 모델 실행과 분리해 포함하며,
정답 작성·프로토콜 검증 비용을 제품의 실행 비용으로 섞지 않는다.

한두 개 성공 사례만 선택하거나 실패를 지우지 않는다. 16회 전체와 조건별 반복을
보고하고, 인프라 실패는 원인과 처리 여부를 따로 기록한다. 같은 입력의 선택적 재시작은
하지 않는다. 독립 사례에서 반복된 coverage/조사 부담/시간 개선이 있고 근거 없는
주장이 늘지 않을 때에만 제한된 효용을 주장한다. 없으면 음성 결과를 보존하고,
확인된 원인을 고친 뒤 새로 정한 미사용 사례로만 다음 평가를 진행한다.

## 후속 실행 v2의 사전 변경

첫 16회 음성 결과와 원본 도구·바이너리·manifest를 보존한다. 같은 표본은 개발 자료로만 쓴다.
새 4개 변경은 기존 표본을 제외하고 고정했으며, Gson의 미사용 적격 표본이 없어 사전에 정한
사전순 Java 저장소 대체 규칙으로 fastjson2를 선택했다. 새 oracle은 제품 질의 전에 고정한다.

제품 MCP는 source-style selector의 실제 USR 후보를 안내하되 `notFound`·모호성을 유지한다.
내용 한도는 16 KiB이고, 페이지·경로 한도를 줄였으면 실제 적용한 값을 명시한다. 이 변경은
첫 실행에서 관찰한 조회 실패·클라이언트 출력 파일 대체에 대응한다. 새 모델 실행 중에는
도구·입력·예산을 변경하지 않는다.

Fastjson2의 원본 core와 전체 test 출력은 compact snapshot이 88,695,953 bytes로 기본
64 MiB 한도를 넘었다. 표본·테스트 범위를 줄이지 않고 제품의 명시적 `--snapshot-max-mib 128`
옵션을 사용한다. v2 manifest에 이 시작 한도도 고정한다. 첫 capture 실패와 실제 메모리 비용은
보존한다. 이 옵션은 JSON 형식·선택·신선도·16 KiB 도구 내용 한도를 바꾸지 않는다.

전체 12회 도구·900초·$3 예산과 두 조건의 공통 source 접근은 유지한다. v1 채점기의 클래스명
뒤 설명에 대한 부분 점수 누락을 회귀 테스트로 고쳤으며, oracle이나 정확한 메서드 규칙은
늘리지 않았다. 새 실행은 이 수정된 채점기까지 해시로 고정한다.

## 후속 실행 v3의 사전 변경

두 번째 16회도 음성이며 원본과 실패한 응답을 보존한다. 정확한 메서드의 최소 영향 페이지도
전역 summary 때문에 16 KiB를 초과한 문제를 확인했다. v3 제품은 CLI `--summary-limit`와
MCP `summaryLimit`으로 요약 축별 항목만 제한하고 원래·반환·생략 수를 명시한다. 선택·영향
후보·경로·한계·탐색 예산은 변경하지 않는다. 기본 CLI 보고서는 전체 요약을 유지한다.

각 저장소에서 다음으로 높은 적격 미사용 PR을 고정했으며, 모델·제품 질의 전에 원본 빌드와
기존 검토 기준을 확인한다. 여러 commit의 PR mail series는 최종 net production diff로 정규화하고
고정 base에 `git apply --check`를 수행한다. 원본 mail series와 준비 실패도 보존한다. 새 PR 테스트는
추가하지 않으며 기존 건너뜀은 실행·통과·oracle 대상으로 세지 않는다. 모델·예산·공통 source 도구와
두 반복·16회 전체 보존 계약은 그대로다.
