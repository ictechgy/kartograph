# 실제 변경·AI 수정 평가

제품 기준은 PR #40의 `bc723c02d100cdb2ec990f5d3d0569e57f67c7e9`다.
표본과 채점 규칙은 결과를 보기 전에 [PROTOCOL.md](PROTOCOL.md)와 [cohort.json](cohort.json)에 고정했다.
실행·채점 도구의 첫 검증 커밋은 `d4e6a81af9d8a858d922473105065e926699dcfd`다.
**첫 24회는 입력 정제 오류가 확인되어 원본 소스 기반 생산성 비교의 유효한 근거로 사용하지 않는다.**
독립 테스트로 확인한 패치 결과와 비용은 오류 조사 기록으로 보존한다. 입력 정제와 질의 인터페이스를
보완하고 [새 표본](cohort-v2.json)으로 후속 검증을 진행한다.

## 실제 버그 재현

모든 숫자는 JUnit 기록의 **통과 / 실패 / 건너뜀**이다. 건너뛴 테스트를 통과나 실행으로 세지 않는다.
원본, 회귀 테스트 주입 상태, 같은 회귀 테스트에 정답 수정을 적용한 상태를 구분했다.

| 표본 | 원래 테스트 | 회귀 테스트 주입 | 정답 수정 후 |
|---|---:|---:|---:|
| Gson #1555 | 1,049 / 1 / 1 | 1,049 / 2 / 1 | 1,050 / 1 / 1 |
| Jackson Core #1309 | 1,399 / 0 / 1 | 1,399 / 1 / 1 | 1,400 / 0 / 1 |
| detekt #7888 | 6,613 / 0 / 6 | 6,613 / 1 / 6 | 6,614 / 0 / 6 |
| ktlint #2983 | 2,768 / 0 / 15 | 2,768 / 1 / 15 | 2,769 / 0 / 15 |
| AnkiDroid #20250 | 1,330 / 0 / 80 | 1,333 / 1 / 80 | 1,334 / 0 / 80 |
| AnkiDroid #19982 | 1,242 / 0 / 106 | 1,242 / 1 / 106 | 1,243 / 0 / 106 |

Gson의 날짜·로케일 테스트 실패는 원래 데이터의 실행과 정답 수정 실행에도 존재한다.
같은 실패를 별도로 유지하며 전체 테스트 성공으로 표현하지 않는다.
Jackson은 배포되지 않은 parent `2.17.2-SNAPSHOT`을 같은 버전의 정식 parent `2.17.2`로 바꿨다.
production 코드와 테스트를 바꾼 환경 보정은 없다.
AnkiDroid는 로컬 시간대에서 알람 테스트가 하루 차이로 실패했다. UTC에서 해당 테스트와 원래 전체
테스트의 통과를 확인한 뒤 두 표본에 같은 UTC 환경을 적용했다.
detekt는 원격 predictive test selection과 CI 환경에서의 자동 재시도를 끄고 원래 전체 테스트를 실행했다.
초기 환경 실패와 중단한 실행도 로컬 원시 증거에 남겼다.

새 회귀 테스트를 추가하기 **전에** 그래프를 보관했다. 추가된 테스트를 수정 전 그래프의 실패 예측
대상으로 세지 않는다. 그래프에 포함된 클래스 선언은 실제 컴파일된 클래스 파일 목록과 대조했다.
Android는 테스트 classpath의 JAR에 들어가는 앱 본체를 놓치지 않도록 컴파일 목적지도 수집한다.
이 입력 선택의 범위와 관찰된 분석 한계는 정확도 판단에 함께 사용한다.

## 실행 경계와 재현

- [실행기](../../Scripts/evaluate-impact-repair.py)는 고정 Git commit을 새 디렉터리에 checkout한다.
  코드 읽기·검색·수정·테스트는 로컬 controller의 허용 목록과 고정 명령으로 수행한다.
  정답 패치·회귀 테스트·정답 변경 파일 목록은 모델의 workspace, 입력, 그래프에 넣지 않는다.
- [독립 채점기](../../Scripts/grade-impact-repair.py)는 별도 checkout에 모델이 만든 production 패치와
  숨긴 회귀 테스트를 적용한다. 실제 JUnit 결과를 report 경로·클래스·테스트 이름·중복 개수로 대조한다.
  정답 실행에서 통과한 테스트의 누락·실패·새로운 건너뜀은 탈락이다.
- [Gradle 입력 수집](inputs.init.gradle)은 각 프로젝트의 task에서 그 프로젝트의 configuration을 해석한다.
  Gradle 9.3의 프로젝트 잠금 규칙과 실제 Android main/test 클래스 포함을 실행으로 확인했다.
- [준비용 init](prepare-tests.init.gradle)은 원래 테스트 task의 의존성을 빌드하고 테스트 실행만 건너뛴다.
  실제 AI 테스트와 독립 채점 명령에는 넣지 않는다. 두 Android 표본에서 클래스 소유자 수가 일치하고
  테스트 결과 파일이 생성되지 않는 것을 확인했다.

모델은 원래 저장소 밖에서 직접 도구 없이 실행하고, 매 요청의 공개 코드·이슈를 `packet-ask`로 정제한다.
교정 첫 실행은 전송기의 일반적인 리뷰 안내 때문에 검토 의견만 반환했다. 이를 실행 준비 오류로
보존하고, system prompt에 승인된 수정 실험과 로컬 controller의 역할을 명시했다.
다음 OkHttp 개발 표본 실행에서는 양쪽 모두 실제 수정·테스트를 수행했고 독립 회귀 테스트 24개가 통과했다.
양쪽 모두 impact 질의를 사용하지 않았으므로 이 결과는 제품의 이점을 입증하지 않는다.

요청 모델은 `claude-opus-5[1m]`, effort는 `low`다. Claude CLI는 보조 Haiku 사용량도 보고했다.
모든 보고 모델 ID와 사용량을 보존하며 비용은 CLI가 보고한 정가 기준 추정치로 다룬다.
요청 하나라도 비용 정보가 없으면 총비용은 unknown이다. 실제 청구 금액이나 통계적 우위로 표현하지 않는다.

원시 소스·패치·classpath 절대경로·대화 기록은 로컬에 두고 공개 결과에는 요약과 지문만 포함한다.
공개 데이터의 고정 revision과 표본 선택 이유는 [cohort.json](cohort.json)에 있다.
이 작은 공개 표본은 모델이 과거에 해당 이슈를 접하지 않았다는 보장이 없으며,
제한된 controller에서의 수정 실험을 모든 코딩 에이전트의 성능으로 일반화하지 않는다.

## 검증 근거

- 명시한 JDK 21 환경에서 수정 후 Python 전체 테스트 100개 통과.
- 자체 분석 6개 계약 통과: 총 2.785초, 예산 15초. 이후 변경은 Python 실행·채점 경계이며 해당 분석 입력은 동일하다.
- 실제 Gson 코드로 독립 채점기 확인: 버그가 남은 패치 탈락, 정답 수정 통과,
  기존 날짜 실패와 건너뛴 테스트는 각각 별도로 유지.
- Android 준비 단계의 클래스 선언: #20250은 4,684개, #19982는 4,413개로 실제 class 파일 소유자와 일치.
- 실제 `packet-ask` 경로에서 공개 fixture의 주석·URL·XML 종료 태그·`UTC`·`/dev/null` 보존과
  알려진 로컬 경로 가림을 확인했다. 비경로 환경값을 공개 소스의 치환 토큰으로 사용하지 않는다.
- 신뢰한 빌드/회귀 패치의 적용 오류는 모델 패치 위반과 별도 상태로 분류한다.
  새로운 비교에서는 심볼 조회와 영향 조회 호출 수도 각각 기록한다.

최종 리뷰·CI·머지·배포 완료를 뜻하지 않는다. 원래 테스트에 대한 사전 영향 점검과 후속 개선의
새 표본 검증도 최종 채점에 포함한다.

## 첫 실제 AI 비교 결과

아래 표는 입력 오류가 있었던 실행의 관측 기록이다. 검토에서 경로 정제 정규식이 공개 소스의 주석,
URL, XML 종료 태그까지 바꾸고 환경값 `UTC`를 본문에서 치환할 수 있는 문제가 발견됐다.
원본 Git commit과 읽기 커서로 대조한 첫 소스 읽기 21건 모두 저장된 내용이 달랐다.
확인 가능한 provider 입력의 읽기 응답에도 변형이 있었고, 일부 후속 입력은 history JSON까지 깨졌다.
따라서 두 조건의 원본 입력 충실성이 성립하지 않는다. 이 표로 제품이나 원본 소스 기반 AI 작업의
생산성 우위를 주장하지 않는다. 모델이 만든 패치의 독립 회귀 결과 자체는 그대로 남긴다.

각 칸은 **source · impact** 순서다. 성공은 숨긴 회귀와 기존 Gold 통과 테스트를 독립적으로 확인한 결과다.
평균 시간은 공통 준비와 모델 작업을 포함하고, 평가자만 수행하는 독립 채점 시간은 별도로 기록한다.
비용은 앞서 설명한 CLI 정가 기준 추정치이며 성공한 실행만 골라 평균 내지 않았다.

| 표본 | 수정 성공 | 평균 총시간(초) | 평균 비용 추정 | impact 조건의 실제 질의 |
|---|---:|---:|---:|---:|
| Gson #1555 | 2/2 · 2/2 | 53.1 · 66.0 | $0.520 · $0.841 | 0 |
| Jackson Core #1309 | 2/2 · 2/2 | 82.4 · 112.7 | $0.507 · $1.162 | 0 |
| detekt #7888 | 0/2 · 0/2 | 160.6 · 167.4 | $1.098 · $1.540 | 0 |
| ktlint #2983 | 1/2 · 2/2 | 160.1 · 145.1 | $1.067 · $1.506 | 0 |
| AnkiDroid #20250 | 0/2 · 0/2 | 244.2 · 260.5 | $0.697 · $1.226 | 0 |
| AnkiDroid #19982 | 2/2 · 2/2 | 229.7 · 229.6 | $0.490 · $0.900 | 0 |

전체 성공은 source 7/12, impact 8/12였다. ktlint 한 사례에서 성공 수와 시간의 차이가 보였지만,
독립된 여러 사례에 반복된 강점이 아니며 실제 그래프 질의는 사용되지 않았다.
따라서 스킬·도구를 제공한 이 제한된 조건의 결과를 그래프 분석 자체의 생산성 향상으로 해석하지 않는다.

처음 Kotlin 8회는 채점기가 유효한 JUnit 표시 이름의 줄바꿈을 거부해 테스트 실행 전 판정이 중단됐다.
모델 실패로 세지 않고 저장된 동일 패치를 수정한 채점기로 다시 실행했다. 이 재실행에서 ktlint 3회가
통과했고 나머지는 실제 테스트 실패가 관찰됐다.
detekt의 두 특정 parameterized test 문맥은 객체의 실행별 identity hash도 이름에 포함한다.
선택적 `detekt-junit-object-identities-v1` 정책으로 소스에서 확인한 report·class·이름 패턴의 비교 키만
보정했다. raw 이름·테스트 종류·개수·실패를 유지하며, 다른 테스트의 의미 있는 `@...` 텍스트나 공백은
전역적으로 제거하지 않는다. 세 실행의 가짜 누락은 해소됐다. 첫 impact 실행은 문서 생성기의 config
delegate 규칙 위반으로 필수 통과 테스트 322개가 실제로 실행되지 않았고, 이 누락은 유지했다.
네 수정의 실제 회귀 실패는 이름 차이와 무관하므로 위 성공 수는 달라지지 않는다.

## 진행 중 발견한 사용 경계

첫 완결 사례인 Gson은 두 반복의 양쪽 조건 모두 같은 패치로 통과했다. impact 조건에서도 실제
질의는 사용하지 않았으며, 준비를 포함한 평균 시간은 source 53.068초 / impact 66.022초,
CLI의 평균 정가 비용 추정치는 각각 $0.520 / $0.841이었다. 이 사례에서 추가 이득은 관찰하지 못했다.
전체 표본의 결론으로 일반화하지 않으며, 불리한 결과도 최종 집계에 포함한다.

첫 실험(v1)의 controller는 `impact`만 제공했다. 주입된 제품 스킬은 심볼 발견에 `query`도 권장하므로
제품 스킬의 전체 흐름을 이 조건에서 실행할 수 없다. 또한 모든 선택·필터 값을 한 JSON 예시에
보여주어 최소 필수 입력과 선택적 필터가 구분되지 않는다. 이것이 질의 미사용의 원인인지는 아직 가설이다.
이 제한은 v1 결과 해석에 남겼고, 24회 실행 중에는 조건을 변경하지 않았다.

후속 개선에서는 같은 저장 그래프에 제품의 `query` 명령을 연결했다. 일반 심볼 이름으로 찾을 수 있고,
파일만 지정하는 `impact` 예시와 필수 선택·선택적 필터를 구분했다. 조회량은 controller 기본 5개이며
제품 CLI 기본 50개와 다르다. 실제 Android `NoteEditorFragment` 조회는 기본 50개에서 응답 한도를
초과했지만, 조정 후 원래 query 문서와 한계 정보를 유지한 6,579자 응답으로 전달됐다.
없는 심볼의 종료 코드 64와 한계 정보도 전달했다. 이 연결 검증을 AI 생산성 향상으로 세지 않는다.
이미 관찰한 표본은 개발 자료로 남기고, 결과를 보기 전에 고정한 [다음 표본](cohort-v2.json)으로 다시 검증한다.

후속 표본의 detekt 준비에서는 `testClasses`가 runtime classpath의 프로젝트 test-fixtures JAR을
만들지 않아, 첫 impact 조건이 모델 호출 전에 capture 종료 코드 2로 중단됐다. 이 준비 실패와 앞선
source 수정의 회귀 실패를 보존했다. 원래 `test` 작업의 의존성을 빌드하고 Test 실행만 건너뛰는
준비 방식으로 누락 JAR을 생성했다. 실제 테스트 보고서는 0개였고, 소스 diff 없이 snapshot의
22,320개 선언 ID와 2,928개 클래스 선언이 원래 입력과 일치했다. 이는 준비 복구 근거이며 속도 향상
측정은 아니다. 수정한 준비 조건을 detekt 양쪽에 동일하게 적용한 네 실행은 별도 기록으로 수집한다.
이미 끝난 Java 여덟 실행의 입력과 결과는 그대로 재사용하며, 문제·원본 revision·숨긴 회귀·모델 예산은
변경하지 않는다.
