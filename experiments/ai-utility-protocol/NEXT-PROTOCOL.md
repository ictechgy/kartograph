# 다음 효용 평가의 준비 조건

2026-09-21 v4 후속 감사에서 도출한 준비 조건이다. **새 코호트를 사전 등록했거나 실행했다는 뜻은 아니다.**
기존 v1–v4 입력·oracle·채점·점수는 보존하며 다음 평가의 성공 사례로 재사용하지 않는다.

1. **입력 준비를 먼저 검증한다.** 지원되는 실제 compiler task의 성공 증거로 snapshot을 자동 캡처하고,
   모델 노출 전에 현재 source·class·build 입력에 대한 `matched`를 확인한다. commit/scope 라벨만 넣은 수동
   snapshot으로 대체하지 않는다. 준비 실패·비용과 불가한 variant는 따로 기록한다. Maven 등 현재 자동 capture가
   없는 표본을 조용히 제외하거나 형식적 witness로 통과시키지 않는다. 지원 빌드만 선정할 경우 그 모집단을 사전에 명시한다.
2. **표본을 새로 고정한다.** 빌드·기존 테스트의 자격 조건, 미사용 표본의 순서와 제외 규칙을 제품 결과를 보기 전에
   정한다. 직접·간접 oracle은 제품 그래프와 독립된 javap·실행한 기존 테스트·원본 선언으로 고정한다.
3. **응답 상한과 과제를 일치시킨다.** 알려진 전체 oracle을 나열하는 과제에서는 oracle이 응답 상한을 넘지 않도록
   사전 자격 조건을 정하거나, 모든 사례에 같은 충분한 상한을 적용한다. 상위 K개 우선순위 과제라면 전체 recall과
   별도로 정의한다. oracle 32개·응답 12개인 v4의 0.375 천장을 새 효용 차이로 읽지 않는다.
4. **선언 identity를 대칭적으로 채점한다.** JVM USR과 정확한 source signature를 독립 선언 목록으로 같은 identity에
   연결한다. 한 예측은 최대 한 선언에만 점수를 줄 수 있고 중복 예측은 중복 가점하지 않는다. 모호한 overload·파일
   수준 답변은 별도로 보고한다. source 조건이 보지 못하는 USR만 정답 형식으로 강제하지 않는다. Java overload,
   Kotlin backtick·extension·property·생성 선언과 잘못된 signature의 회귀 검증을 모델 노출 전에 끝낸다.
5. **실제 응답 근거를 검토한다.** oracle 밖 대상은 미판정으로 분리한다. 이들을 오탐으로 세려면 원본 source·호출
   근거의 별도 판정이 필요하다. 조건명 대응표를 숨겨도 답변에 graph/freshness 언급이 남으므로 완전한 맹검을 주장하지
   않는다. 자동 채점·AI 보조 검토·사람 검토의 수행자를 구분한다.
6. **준비와 사용 비용을 함께 남긴다.** 첫 설치·빌드·capture·MCP 시작·질의·갱신·시간·비용을 분리한다. 도구 호출은
   강제하지 않고 두 조건의 정보·시간·출력 예산을 동일하게 고정한다. 실패·무효 응답·예산 소진도 전체 분모에 남긴다.
7. **실행 전 고정을 확인한다.** 위 조건을 만족한 코호트·모델·prompt·예산·scorer·선언 목록·oracle·제품 바이너리·입력
   해시와 측정 규칙을 manifest로 고정한다. 그 이후 결과를 보고 조건을 바꾸면 별도 실험으로 기록한다.

이 준비 조건만으로 AI 생산성이 좋아졌다고 주장할 수 없다. 실제 새 코호트의 전체 결과와 원본 근거가 필요하다.
