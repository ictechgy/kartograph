# 변경 영향 점검 후속 완료 기준

2026-09-12 사용자 요청으로 [초기 구현·채점](../experiments/change-impact/README.md) 이후의 다섯 과제를 진행한다.
기준은 PR #36의 `e505a92`다. 수정 전 영향 점검, 사람·AI 공통 질의, 런타임 관계의 정적 근거,
CI 갱신 속도라는 원래 목표를 유지한다. 작업을 다음 일곱 단계로 나누되 최종 완료는 배포본 설치까지 확인한다.

| 단계 | 산출물 | 완료를 입증할 근거 |
|---|---|---|
| 필드 값 흐름 | 변경 가능한 static 필드와 reflection 읽기에 대한 제한된 값 분석 | 기존 `reflective_field`를 바꾸지 않고 실제 사용 생성자의 영향 경로 복원; Java/Kotlin·재대입·unknown·상속·초기화 순환·미사용 대조군 |
| 신선도 | 빌드가 생성한 입력/출력 지문과 snapshot 검증 | 오래된 class에 최신 commit 라벨을 붙인 경우, 시각을 보존한 내용 변경, 삭제·classpath·variant 변경 거부; 동일 입력의 재현성과 비용 |
| 컴파일러 근거 | 인라인 전 상수 참조 및 선택 DI 간선의 제품 입력 | fixture 매핑에 의존하지 않는 Java/Kotlin JVM identity, 실제 Dagger 선택, stale/실패/증분/병렬 빌드 수명주기 |
| 영향 탐색 | 큰 후보 집합의 설명 가능한 요약·우선순위·후속 질의 | Anki의 20,699개 후보에서 필요한 경로를 찾는 작업량·출력량 측정; 전체 후보와 잘림·미해결 정보 유지 |
| 채점 확대 | 고정된 실제 Java/Kotlin 변경 코호트와 AI 수정 작업 비교 | 기존 테스트의 출처와 실패 재현, 숨긴 정답, 동일 모델/예산, 튜닝과 평가 표본 분리, 실패·제외 결과 공개 |
| CI 자동화 | main/test root와 variant를 연결한 빌드 후 snapshot·질의 | 별도 JVM/Android 소비 프로젝트 설치, 실패 빌드와 cache 재사용, 최소 AGP/Gradle 및 JDK 17/21 |
| 릴리스 | 문서·VERSION·검증된 배포물 | Claude 리뷰와 최종 commit CI, 두 번 빌드 재현성, GitHub/Plugin Portal 공개와 독립 설치 후 실제 기능 실행 |

## 평가와 진행 규칙

- 도구 호출 횟수 감소만으로 실제 수정 성공률이나 사용자 생산성 향상을 주장하지 않는다.
  동일 작업의 누락·검토량·수정 성공·시간·비용을 비교하고, 독립 사례에서 반복되는 실익을 확인한다.
- 런타임 모델이 지원하기로 한 입력에서는 실제 실행 대상과 미사용 대조군을 함께 검증한다.
  unknown 값이나 입력 밖 호출을 구체적인 대상으로 바꾸지 않는다. 보존은 호출 경로와 구분한다.
- source/class 지문 일치는 입력 무결성의 증거다. 빌드가 해당 source를 실제로 처리했는지는 별도의 빌드 생성 기록으로 검증한다.
  임의 호출자 선언이나 시각 비교를 빌드 증명으로 승격하지 않는다.
- 기본 bytecode/metadata 원천과 query 호환성을 유지한다. compiler/DI 보강은 검증된 opt-in 입력으로 제공하며
  collector 의존성을 분석기 runtime에 넣지 않는다.
- 각 기능은 변경 전 실패·수정 후 검증, 리뷰·CI·머지를 거친다. 현재 상태와 원시 로그는 PR과 실행 기록을 따른다.
  기존 사용자의 HANDOFF 변경은 별도로 보존한다.
- MCP는 이미 제공하는 스킬의 선택적 대안이다. 증분 인덱서는 빌드·capture·질의를 분리한 CI 실측으로 필요성을 판단한다.

## 시작 상태

초기 `impact`·compact snapshot·스킬·CI helper는 구현됐다. 이 문서의 후속 기능, 확대 채점과 릴리스는
각 단계의 실제 근거가 모이기 전까지 완료로 간주하지 않는다.
